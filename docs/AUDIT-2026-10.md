# Card Parlour audit — 9 Oct 2026

Audited on `main` at `618f6aa` (package `0.3.60`). This pull request only adds the audit, the build log, and the agent workflow, and bumps the package to `0.3.61` so the Home stamp changes. Nothing in the game changed. Screenshots are local, at the sizes below. Average is a failing grade against "a stranger would pick this over Trickster." The table can look handsome. The product around it is still a phone app with a long home scroll, a fiddly friends lobby, and no front door.

## What works

- Home offers Hearts, Spades, and Euchre, a friends host sheet (game, then Kitchen / Club / other presets), a room-code join, career counters, and daily challenges. The stamp `v0.3.60 · build …` is real. On this audit build it rendered `v0.3.60 · build 2026.10.09.2124` locally. Live is still `2026.09.15.2315`.
- Solo Hearts reaches the pass-3-left table. Solo Spades reaches a bid pad with Nil, 1–13, and Lock in, and other seats already show bids. Solo Euchre reaches order-up, dealer discard (six cards, kitty marked), round-2 "Name trump" (turned-down suit removed), and "Go alone?".
- A Hearts hand can be finished. The recap ("Hand complete", ranked rows, Next hand, Home, Last trick, Share) is the most finished screen in the app. Sticky actions stayed on screen at 390, 360, and 1280.
- Settings edits house rules, speed, and the named seats (You, Angie, Scott, Heather) with portraits.
- Stats lists six daily goals and an All games section.
- The table menu (Keep playing, Settings, Home, Start over, Quit) sits above the table and says the match is autosaved.
- Friends multiplayer, locally: host Ada and guest Bea both saw room code `BQDN` on a Kitchen Hearts table. Deal stayed disabled until both tapped "Wait for friends · or fill bots". After that vote, both were in a Hearts pass.
- Reconnect code exists. Lobby grace is 30 s, match grace is 90 s, idle close is 10 minutes (`src/multiplayer/roomSession.ts`). The banner copy is "Reconnecting to the table…" and "{name} stepped away" (`ConnectionBanner.tsx`). Replacing a gone player is a host vote, not automatic.
- Tests cover a lot of engine and room behavior. Open GitHub issues: none. Open pull requests: none.

## What is broken or clunky

Honest read of the screenshots. Paths are relative to the repo.

**Home is a phone column, and the important footer is below the fold.** At 390×844 the first screen ends around Today's challenges. Settings, Host, and the three games fit. The version stamp, the "Stats · Goals · Trophies" button, and the install tip do not. See `docs/audit-2026-10/screenshots/home--iphone-390.png` and `home-footer--iphone-390.png`. At 1280×800 the same column sits in a wide empty field and the challenges are cut off (`home--desktop-1280.png`).

**360 px clips the game blurbs.** `home--android-360.png` truncates "solo vs AI", "partners", and "loners".

**Two controls share one accessible name.** The top Career pill and the wins/trophies/goals strip are both `aria-label="Career stats, trophies, and goals"`. A strict accessibility query finds two buttons. That is a real bug, and it will flake any test that clicks "Career" without `.first()`.

**The install tip is easy to miss and sometimes wrong for the window.** It is under the challenges. With an iPhone user agent it correctly says "Add to Home Screen" (`pwa-tip-ios--iphone-390.png`). With desktop Chrome squeezed to 390 px it says "Install on desktop" and "Click Install below when available" even though no install button is showing (`home-footer--iphone-390.png`). Platform comes from the user agent, not the viewport.

**Hearts pass does not look like a four-seat table.** The felt is a big "Hand 1", three empty slots, and Pass Left. The other players disappear. The 13-card fan crowds the right edge; the last card is clipped at 390 and at 360 (`hearts-pass--iphone-390.png`, `hearts-pass--android-360.png`). The same clip shows up on the online pass (`mp-table--iphone-390.png`).

**Spades bid is usable and still cramped.** At 390 the pad (Your bid, 1–13, Nil, Lock in) is on the felt and seats still show numbers (`spades-bid--iphone-390.png`). The status line (DEAL, bags, tricks) is dense. This is better than a pad that covers the table. It is not yet a premium bid.

**Euchre bidding is the strongest in-game layout.** Order-up, discard, name-trump, and loner all fit at 390 (`euchre-bid--iphone-390.png`, `euchre-discard--iphone-390.png`, `euchre-name-trump--android-360.png`, `euchre-loner--iphone-390.png`). On stick-the-dealer the banner says you must name trump, and the panel still draws a Pass button (`EuchreTrumpPanel.tsx` always renders Pass). That is a rules-UX hole for the test suite, not something this audit proved the engine accepts.

**The hand recap is good.** `hearts-hand-recap--iphone-390.png` shows rank, avatar, this hand, total, Next hand, and Home without the actions falling off. Desktop is the same card floating on a lot of felt (`hearts-hand-recap--desktop-1280.png`). A match-end overlay was not captured: instant speed and automated taps finished one hand in 90 seconds and did not reach race-to-50.

**Friends lobby can feel stuck.** `canStart` in `src/multiplayer/lobby.ts` returns false while any empty seat remains unless every human has voted to fill those seats with AI. The gold "Deal now" button is disabled the whole time. The line that is actually required ("Wait for friends · or fill bots") and the deal button sit below the felt, so a 390 px and especially a 360×740 capture clips them (`mp-lobby-host--iphone-390.png`, `mp-lobby-guest--android-360.png`). Copy on that screen: "You stays on your chair" (`FriendsLobby.tsx`). House-rule pills are drawn twice. There is an SMS share button. It opens the device share sheet. This audit did not send a message.

**First online hand opens under the wrong coach.** With coach flags unset, both browsers got "Quick tip 1 / 3 — Play a card" on top of a pass-3-right hand (`mp-text.txt` before the retake). The tip is about playing a card. The player is passing. It also covered any reconnect UI.

**Reconnect was not shown.** After both clients were in the hand, `context.setOffline(true)` on the host did not produce "Reconnecting…" or "stepped away" in the body text within about a second (`docs/audit-2026-10/mp-text.txt`). The screenshots `mp-reconnecting--iphone-390.png` and `mp-pause--android-360.png` are the pass screen, not a banner. The banner component and the 90 s grace are in the code. This pass did not prove they appear, and it did not prove they are broken. Background, radio change, and refresh were not exercised. That is the A1 gap.

**Local dev CORS is narrower than the docs imply.** `src/multiplayer/origins.ts` allows `http://127.0.0.1:5173` and `http://localhost:5173` only. A Vite server on 5174 can preflight and then the browser drops the create-room POST. `wrangler dev` itself is fine.

**No protocol version.** `hello` is `{ type, token?, name }`. A cached service worker can talk to a future Worker with no version check and no "update available" path.

**No turn watchdog.** A seat can sit until the 90 s grace or the 10 minute idle close. Nobody plays a legal card when a turn simply stalls.

## What the brief got wrong

Checked against the repo and the live site on 9 Oct 2026. These items in the market-ready brief do not match:

- **Lint is not clean.** The brief treats `npm run lint` as a pass/fail gate. It exits 0 with 5 warnings.
- **"No tutorials" is too strong.** There is no 60-second walkthrough, but the first deal opens a "How to play" coach, and online play opens "Quick tip 1 / 3". Daily challenges already exist on Home and on Stats. They are not a shared seeded deal.
- **The README is behind the app.** It still tells a newcomer to add `YOUR_USER`, push `master`, and turn on Pages by hand. It does not mention the Worker, the real Pages URL, or that Spades and Euchre engines live beside Hearts. `vite.config.ts` uses `base: './'`, which the README does get right.
- **`docs/online-multiplayer-scope.md` is a July 2026 draft** whose "what we lack" list (transport, lobby, projection) is already built. `docs/superpowers/specs/2026-08-12-online-multiplayer-design.md` still describes a destination that includes accounts, table chat, and matchmaking. The current product decision is no chat.
- **History is not "PRs #1–#8 and then silence."** Those eight PRs are the merged ones. A lot of later work, including `618f6aa` (v0.3.60), landed as direct commits on `main`. The last of those is 15 Sep 2026, which the brief got right.
- **The brief's live version is right.** 0.3.60, build `2026.09.15.2315`, last commit 15 Sep 2026.
- **Test counts are right.** 444 passed, 4 skipped, 58 files. E2e is Desktop Chrome only (`playwright.config.ts`). One local e2e run failed for the reason above.
- **Worker shape.** `worker/room.ts` is a thin Durable Object shell (221 lines). The rules live in `src/multiplayer/roomSession.ts` (about 1,000 lines). There is no protocol version on `hello`.
- **Cloudflare plan.** Still unknown. Not guessed.
- **Brand and domain.** Still not chosen.
- **`AGENTS.md` at the start of this audit said to push `main` yourself.** This pull request replaces that with the pull-request workflow.

## Grade

The engines, the room server, and a few screens (Euchre bid, hand recap, Spades bid pad) are ahead of a prototype. A stranger on a phone still gets a clipped hand, a home page that hides its own version, a friends table that will not deal until everyone finds a second button, and no reason on the public URL to trust the site, find it in search, or come back tomorrow. That is a failing grade for market-ready, and a fair grade for a strong hobby build.
